Ballpark — Item Import (Create from File)

Supplier bulk-creates draft items from a spreadsheet. A small staging-ETL: load relaxed → validate/quarantine → transfer only the clean rows → purge staging, so production never sees the garbage. SKU-keyed upsert makes re-imports idempotent. Everything lands as drafts → normal approval. V1 scope

The pipeline — load · transform · review · transfer · purge

Staging-ETL lifecycle

  • LOAD (relaxed): accept any structurally-valid file; every cell lands as nullable text in import_rows — a bad value never crashes the upload.
  • TRANSFORM (quarantine): cast strings → numbers, check required fields + codelist membership. Rows that break rules are marked is_quarantined = true with validation_notes, not dropped.
  • TRANSFER (atomic): on confirm, one transaction INSERT … SELECTs the clean rows into items as drafts. Instant at supplier scale (hundreds of rows).
  • PURGE: truncate the batch's staging rows after transfer — production never carries import junk.
  • Staging = tables, not a schema (import_batches + import_rows) — same isolation, no fight with the migrate-schemas.js 3-schema model.

Template & validation

  • Per-category template (CSV + xlsx): name, subcategory, unit, base price, install cost/unit, lead time, description. Subcategory is a picked column (from the reference sheet), not free text — no AI needed in V1.
  • Reference sheet lists valid subcategories (for the chosen category), units and tiers — suppliers pick known values.
  • Validated per row against the existing StoreItemCreateSchema + codelists (unknown unit / bad category / non-numeric price / missing name → quarantined with a reason).
  • Org from JWT — never trusted from the file.

SKU-keyed upsert — "handled or provided"

  • Nullable items.sku = the supplier's own key when they have one, else NULL (our id is the real PK).
  • Partial unique (org_id, sku) WHERE sku IS NOT NULL AND deleted_at IS NULL — provided SKUs are unique per org; any number of NULL-SKU items coexist.
  • Provided SKU → upsert on (org_id, sku): a re-import cleanly updates the existing draft (catalogue refresh).
  • No SKU → dedupe on name (items(org_id, lower(trim(name)))) → skip + report.
  • So the skip-vs-update question is keyed, not a global toggle: SKU = update-in-place, no SKU = skip.

Schema footprint

  • New (staging, all 3 schemas): import_batches (org, filename, status, counts, audit) + import_rows (batch_id, row_num, raw + nullable-text cols, is_quarantined, validation_notes, target_item_id).
  • Additive: items.sku (nullable) + the partial unique index.
  • Everything else already exists — attributes, kind, subcategory_id, images, pending_classification, the draft→approval flow. No core rewrite.
