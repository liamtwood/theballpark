How a request flows

  • User opens app.ballpark.dev → Vercel serves the Angular bundle
  • Bundle hits /api/* on the Railway-hosted Node API
  • API validates JWT cookie, sets app.current_user_id session var
  • API queries Supabase Postgres via the pooler (Supavisor on :5432)
  • Audit trigger stamps updated_by from current_user_id()
  • Response returned as JSON
  • External calls (Resend / Google OAuth / Unsplash / Anthropic) fan out from the API only — frontend never touches them directly

Future-proofing v2 work

  • Runtime-configurable API URL — /runtime-config.json loaded at boot. No rebuild needed to point at a different API.
  • Env-driven config in API — no hardcoded vendor URLs. Easy swap.
  • One token bridge — Ballpark's --theme-* tokens map to PrimeNG Aura design tokens in a single file. No .p-* overrides scattered.
  • Wrapped external services — StorageService / EmailService abstractions so vendors can be swapped without touching feature code.
  • Self-host story — deferred for now. The above gates keep the option open: deliver as Angular static dist + Docker image + Postgres schema script + Google OAuth env vars.
Source of truth: schema migrations live in server/src/db/migrate-schemas.js. Every column add / table create writes to all three schemas (public, preview, master) explicitly — see WORKING_STANDARDS for the rule. UUIDs are generated with gen_random_uuid() (PG13+ built-in, schema-portable).

⚠ DB host — confirm: migrate-schemas.js:10 states the database is Railway PostgreSQL (Node connects as owner, bypassing RLS); the Supabase SDK is present but not the primary DB path. The "Supabase-managed" labels above may be stale — verify the host before relying on them.
